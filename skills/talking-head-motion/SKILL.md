# 口播动效（talking-head-motion）

把一条横屏真人口播，做成「人始终在场、每句话有画面、音效跟着动作走」的短视频。
底座是 Remotion（用 React 写动画、渲染成 MP4），模板在 `template/`。

**核心分工**：AI 产出零件（分镜初稿、图卡动画、字幕、音效点位），人做导演（选题、口播、每句话怎么排、挑版本）。
所以这个流程的每一步都要把结果拿给人看、让人用大白话改。

## 开始之前

1. 读 `references/style-card.md`：默认风格是「白底蓝光」。如果用户有自己的风格卡，用他的。
2. 确认素材：原始口播视频（横屏 16:9）、口播稿（有的话）、截图/录屏素材、这期最想突出的一句话。
   拍摄要求见 `references/shooting-checklist.md`，可以在拍之前发给用户。
3. 视频文件很大时，不要让用户往聊天里拖，改为读取他电脑上的素材文件夹。

## 流程（先声后画）

1. **声音先定稿**
   - 人声：降噪、轻压缩；整体 1.1 倍速（保留音调），目标语速约 6.3–6.6 字/秒。
   - 剪掉气口和句间多余停顿（> 0.3 秒的都要看一眼）。剪切点尽量藏在图卡出现的时候。
   - 有口播稿时用稿子对齐时间；没有时先做语音识别，再对照画面校错字。
2. **逐句分镜**（`references/storyboard.md`）
   - 一句话一个画面意图。每句选一种排版状态：`full` 全屏口播 / `pip` 图卡 + 小圆头像 / `cutout` 原位抠像 + 图卡。
   - 状态只在句子边界切换，交接一律 0.3 秒淡入淡出，人不移动位置。
   - 输出一张表给用户看（时间、他说的话、画面），让他用大白话改。
   - **风格没把握时，先渲染 3–4 张静帧让他挑，再做整片。**
3. **写进模板**：把分镜填进 `template/src/shots.js`，字幕填进 `template/src/subs.js`，全片设置在 `template/src/config.js`。
4. **节奏检查**（`references/pacing.md`）：跑 `node tools/check-pacing.mjs`，内容出全后停留超过 1 秒、或者两镜之间有空档的地方都要改。
5. **音效**（`references/sound.md`）：模板会按动作自动挂音效（同一动作同一声音，和动画同帧）。只用真实录音，不要程序合成。
6. **打码**（`references/masking.md`）：只针对可能带来法律风险的信息（别人的公司名、邮箱、手机号、ID），小块马赛克，不要大范围糊。
7. **渲染**：先出几张静帧检查，再整片渲染。只交「有音效」的版本。字幕（`references/subtitles.md`）烧进画面，同时导出一份 `.srt`（`node tools/make-srt.mjs`）方便用户在剪映里改。
8. **配乐由用户自己在剪映里加**（`references/music.md` 里有无版权风险的来源和音量建议）。
9. **发布包**（用户在剪映剪完后）：
   - 封面：横屏 4:3（1440×1080）和竖屏 3:4（1080×1440），规则见 `references/cover.md`。
   - 各平台标题、简介、话题、B 站章节时间点、顶部进度条分段，见 `references/publishing.md`。

## 每期结束后

把用户这期提的每条修改记下来（他说了什么、改成了什么、为什么）。
同一类修改出现两次以上，就写进他的风格卡或这份 skill 的规则里。这是这个 skill 持续进化的方式。

## 不要做的事

- 不要用合成或 AI 生成的音效，这是「AI 味」的主要来源。
- 不要让画面静止等待：空档要用素材（录屏、实玩画面）填上，或者直接剪掉。
- 不要把录屏定格当停留；素材是动态的就用动态。
- 讲到具体产品/作品时，只放素材里最精彩的几秒，不要太长。
- 不要给全片大面积打码，也不要漏掉别人公司名这种有风险的信息。
