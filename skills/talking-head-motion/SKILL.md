# 口播动效（talking-head-motion）

把一条真人口播（横屏或竖屏都行）做成「人始终在场、每句话有画面、音效跟着动作走」的短视频。
底座是 Remotion（用 React 写动画、渲染成 MP4），模板在 `template/`。

**核心分工**：AI 产出零件（分镜初稿、图卡动画、字幕、音效点位），人做导演（选题、口播、风格、每句话怎么排、挑版本）。
**省钱原则**：先用静帧和几秒的小动图让人确认方向，再做整片。用户没勾选的部分一律不做。
**带路的命令**：进 `template/` 跑 `npm run next`。它看这期做到哪了，只告诉你现在该做的那一件事（从放素材到出成片都覆盖）；拿不准下一步就跑它，照它说的做。

## 第 0 步：先问用户这次要做哪些部分

开始任何生成之前，先让用户**点选**（不要让用户自己打字改 `[x]`）：

1. 先问一道单选题：「全部都要」还是「我自己挑」。选「全部都要」就等于全选，直接进入第 1 步。
2. 同时问一道单选题：做「横屏（16:9，B 站、视频号横屏）」还是「竖屏（9:16，抖音、小红书、视频号竖屏）」。写进 `config.js` 的 `orientation`。
3. 选「我自己挑」，再问两道**多选题**（Claude Code 里用 AskUserQuestion，`multiSelect: true`，每题最多 4 项）：
   - 画面：图卡动效 / 章节卡·便签·小标签 / 小头像 / 字幕
   - 声音和发布：音效 / 配乐 / 封面 / 发布文案
4. 没有多选提问工具的环境：给一个带复选框和「全选」按钮的小网页（`tools/module-picker.html`），用户点完复制结果发回来；实在不行才列编号清单。

每个选项都要带一行大白话说明（提问工具的选项 description 填这一行），第一次用的人不一定懂这些词：

| 模块 | 给用户看的说明 | config.js 开关 |
|---|---|---|
| 图卡动效 | 讲到重点时，画面切到一张会动的信息卡：截图、要点清单、数字等，帮观众看懂 | `modules.cards` |
| 章节卡 / 便签 / 小标签 | 人在说话时叠在画面角落的小卡片：章节卡显示「第几部分」，便签写一句重点，小标签说明「这是什么」 | `modules.overlays` |
| 小头像 | 画面切到信息卡时，把你缩成角落里的一个小窗，观众始终看得到你 | `modules.avatar` |
| 字幕 | 画面底部的文字，重点词变色；另外给一份字幕文件，方便在剪映里改 | `modules.subtitles` |
| 音效 | 画面上有东西出现时的短促声音，比如「啪」「叮」「嗖」，不到 1 秒，跟着动画响 | `modules.sfx` |
| 配乐 | 整段视频底下轻轻放的背景音乐，推荐几首可以商用、不侵权的曲子给你试听 | `modules.music` |
| 封面 | 视频在列表里显示的那张图，出横屏和竖屏两张 | — |
| 发布文案 | 抖音、小红书、视频号、B 站发布时要填的标题、简介、话题 | — |

没勾的模块：不出样板、不写分镜、不渲染、不写文档。比如没勾字幕，就不做语音识别对字幕；没勾配乐，就不推荐曲子。
把选择结果写进 `template/src/config.js` 的 `modules`。

## 第 1 步：听内容，判断类型

1. 有口播稿就读稿；没有就先做语音识别（中文可用 sherpa-onnx + SenseVoice 等本地模型）。
2. 看几帧画面（ffmpeg 每秒抽一帧拼成一张图）。
3. 判断内容属于哪一类（`references/style-picker.md`）：科技 / 生活 / 家庭 / 知识 / 商业 / 美食旅行。拿不准就选两类各出一部分。
4. 用一句话告诉用户你的判断：「这期讲的是 ×××，我按『生活类』出风格样板」。

## 第 2 步：出风格样板（只针对勾选的模块）

1. 从这期口播里挑几句话，填进 `template/src/samples.js`，让样板看起来就是这期视频。
2. 运行 `node tools/make-samples.mjs --category <类型>`（或 `--styles a,b,c` 指定）。每套风格出：
   - 4 张静帧：全屏口播 + 章节卡 / 三点小卡 / 截图窗口 / 清单（都带字幕和小头像）
   - 1 段 4 秒小动图：带这套风格的动效和音效包，能听到声音
   - **零件对照表**：把几套风格拆开，配色、字体、卡片、字幕、动效和音效按 A / B / C / D 并排，最下面一行是四种头像形状（圆形、圆角方形、正方形、竖椭圆）。用户靠这张图逐项挑。
   - `样板说明.md`：文字版对照
3. **竖屏**：加 `--portrait`。先用一套风格比三种竖屏版式（`--styles <一套> --portrait --layouts split,float,pip`），让用户挑版式，写进 `config.js` 的 `portraitLayout`；再按选定版式出这一类的几套风格（`--category <类型> --portrait --layouts <选定的>`）。三种版式：
   - `split` 上图下人：讲图卡时上半屏放卡片、下半屏放人，字幕挪到交界处。最常见，卡片和人都清楚。
   - `float` 人全屏 + 浮卡：人一直全屏，卡片浮在胸前，脸始终露着，真人感最强；卡片会小一些。
   - `pip` 小头像 + 满屏图卡：和横屏一样，卡片最大，适合截图多、信息密的段落。
4. 每一类至少 3 套，可以再加 1 套别的类当对照。勾了配乐就按 `references/music.md` 给 3–5 首候选曲的试听链接。
5. 把总览图、小动图和说明发给用户。

## 第 3 步：让用户挑选或混搭

先问「整套选一个」还是「逐项混搭」。混搭时逐项提问，每项一道单选题，选项是「A 的」「B 的」「C 的」，再加一个「都不要，换一种」（提问工具每次最多 4 道题，分两轮问完）：配色、字体、卡片样式、字幕样式、动效、音效包、头像形状（1–4）、头像位置（左上 / 右上）、配乐。
- 只喜欢某一整套：直接选那一套。
- 混搭：比如「配色要 A，字体要 B，头像要 C」。写进 `config.js`：
  `style: {base: 'travel-1', font: 'travel-2', avatar: 'oval'}`（每项可以写风格编号或零件名，零件名见 `src/styles.js`）。
- 用 `--mix` 出一张混搭后的确认图，用户点头后再往下走。
- 选定的结果记成这个用户的风格卡（`references/style-card.md` 的格式），下次直接用，不用再挑。

## 第 4 步以后：做整片（先声后画）

**不知道现在该干什么，就在 `template/` 里跑 `npm run next`。** 它会看这期做到哪了，只告诉你现在该做的那一件事；做完再跑一次，前一步没过关不会放你去下一步。下面是它带你走的顺序。

三条规矩（工具已经替你守着，不要绕开）：
- **不写秒数**：分镜表按句子编号写（`say: 'S03-S05'`），每一镜、每个元素什么时候出现由程序算。
- **不估坐标**：脸在哪、要框的字在截图上哪里，由 `npm run measure` 量；不要自己目测填数字。
- **不靠眼睛验收**：`npm run check` 说有错就是有错，改到没有错误为止；提醒逐条看，能改的改掉。

1. **声音先定稿**（`references/cutting.md`）：把口播剪紧。
   - 素材还没剪：原始口播（和另外录的声音，如果有）放进 `template/raw/`，`npm run raw` 逐句识别并先标出疑似重讲 → 在 `src/takes.js` 里把不要的句子改成 `keep: false` → `npm run cut` 剪出 `public/talk.mp4`，句子时间轴也一起生成。下刀位置由程序按量出来的停顿定，不用算秒数。
   - **气口松紧和要不要加速，先问用户**：`npm run raw` 会报语速（日常聊天约 4–5 字/秒，节奏紧凑的口播约 6.3–6.6 字/秒）和建议。用一道选择题让用户定，写进 `config.js` 的 `cut.pause` 和 `cut.speed`；用户说了才加速，加速保留音调。
   - 把「去掉了哪几句、为什么」列给用户，他同意再剪。剪完看验收报告，提示可能切到字的地方要处理。
   - 口播已经剪好了：直接放到 `template/public/talk.mp4`，跳过上面几条。
   - 不降噪、不调色。
2. **量一量**：`npm run measure`。量出口播是横是竖、多长、脸在哪，写进 `src/measured.js`。小头像取哪块、横竖互转保留哪块都按它算；原片和成片方向不一致、会放大发虚时它会提醒。
3. **句子时间轴**：用 `npm run cut` 剪出来的口播已经带了句子时间轴，这条跳过。口播是直接放进来的，跑 `npm run timeline`（有专有名词加 `-- --vocab "Muse,Claude"`；没装语音识别就用剪映导出字幕，`-- --srt 字幕.srt`）。它把口播按停顿切开逐段识别，每句话编上号（S01、S02…）写进 `src/sentences.js`。
   然后**对稿**：只改每一行的 `text`——对照口播稿改错字、给关键词加 `[方括号]`、英文词补中文（`references/subtitles.md`）。不改 `id / from / to`，不增删行。
   跑 `npm run srt`，把字幕文件交给用户过一遍错字，再往下走（字幕烧进画面就改不了了）。
4. **对素材，再逐句分镜**（`references/storyboard.md`，完整范例 `references/example.md`——第一次做先读范例）：先跑 `npm run needs`，看哪些话在讲具体操作却没有截图录屏，问用户能不能补。然后写 `src/shots.js`。每一镜写它对应哪几句话、用哪种画面状态、放什么卡。卡片菜单看 `npm run cards`。
   每张卡写一句 `why`：观众第一次看到它能明白什么。写不出来的卡就删；观点、感受、过渡句不配图，留给人脸。
   画面的来源按这个顺序：真素材 → 动作卡（`chat` / `flow` / `doc`，把动作演出来）→ 文字清单。
   讲操作放录屏卡（`screen`），讲截图里的某个东西用截图卡（`image`）加 `focus` 框出来；用了 `focus` 就再跑一次 `npm run measure`，它去图上找那几个字的位置。
5. **检查**：`npm run check`。填错的字段、对不上的词、放不下的字、太短的镜头、缩得太小的截图、连续干讲太久，都会用大白话指出来并告诉你怎么改。
6. **给用户看**：`npm run storyboard`（出 `out/分镜表.md`）和 `npm run stills`（每一镜一张静帧 + 总览图）。发给用户，让他用大白话说「第几镜换成什么」，改完重跑第 5、6 步。
7. **音效**（`references/sound.md`）：模板按动作自动挂选定音效包里的声音，和动画同帧。只用真实录音。
8. **打码**（`references/masking.md`）：截图里的真名、公司名、金额、邮箱，在卡片上写 `mask`，只糊那几个字。
9. **渲染**：`npm run render`（检查没过不会开始渲染）。开了音效会一次出两条：有音效版和无音效版，两条都交给用户。字幕烧进画面，`npm run srt` 导出 `.srt`。
10. **配乐**：用户选了曲子就放到 `public/`，打开 `modules.music`，模板会只在图卡段落把音乐抬起来、口播时压低；也可以让用户自己在剪映里加。
11. **发布包**（用户最后剪完后）：封面见 `references/cover.md`，各平台文案见 `references/publishing.md`。

## 每期结束后

把用户这期提的每条修改记下来（说了什么、改成什么、为什么）。同一类修改出现两次以上，就写进他的风格卡或这份 skill 的规则里。

## 不要做的事

- 不要跳过第 0 步直接出整片。
- 不要在分镜表里写秒数、不要目测坐标、不要跳过 `npm run check`；素材里没有的画面不要编（检查器会查文件在不在）。
- 不要用合成或 AI 生成的音效和配乐，这是「AI 味」的主要来源。
- 不要让画面静止等待：空档用素材填，或者剪掉。素材是动态的就用动态。
- 讲到具体产品 / 作品时，只放素材里最精彩的几秒。
- 不要大面积打码，也不要漏掉别人公司名这种有风险的信息。
