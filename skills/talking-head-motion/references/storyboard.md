# 逐句分镜

## 原则
1. **先声后画**：口播定稿、剪紧之后，才按句子排画面。
2. **一句话，一个画面意图**。约每 1.5–2 秒要有一次画面变化（新卡片、新一行、框出重点、切状态都算）。
3. **排版状态只有三种**，切换只发生在句子边界：
   | state | 画面 | 适合 |
   |---|---|---|
   | `full` | 全屏口播，可叠章节卡 / 便签 / 小标签 | 观点、过渡、情绪句 |
   | `pip` | 图卡为主，人在小窗里 | 截图、录屏、数据、列表、产品素材 |
   | `cutout` | 原位抠像，图卡摆在人旁边 | 总结、对比、「人站在信息旁边」 |
4. 角落小标签说明「这是什么」（如「某某做的游戏 · 实机画面」）。
5. 开头不直接给结论：先放最抓人的素材几秒，再说观点。结尾回到开头，带着变化。

## 这句话该配什么（照着选）
| 这句话在干什么 | state | 放什么 |
|---|---|---|
| 讲操作、演示怎么点 | `pip` | 录屏卡 `screen`：素材占满，人在小窗；讲到哪个按钮用 `focus` 框哪个 |
| 讲截图里的某个东西（一条消息、一个设置） | `pip` | 截图卡 `image`（或带窗口边框的 `window`）+ `focus` 框出那几个字；长图加 `crop` 只显示那一块，或 `scroll` 滚动着看 |
| 讲一个动作（「发给它」「它回复」「生成一份」），但没有真截图、真录屏 | `pip` | **动作卡**，把动作演出来：`chat`（对话：打字、发文件、对方回复）、`doc`（文档：扫描、划重点、盖上结果）。不要退成文字清单 |
| 讲一件事怎么运转、东西从哪到哪 | `pip` | `flow`（流程：几站依次亮起） |
| 列几个并列的点、几个步骤（确实只是要点，不是动作） | `pip` | `cards3`（2–4 个短词）或 `list`（2–6 行） |
| 报一个数字 | `pip` | `stat` |
| 引用别人的话 | `pip` | `quote` |
| 一句结论 | `pip` | `pill`；或者放在上一张卡的 `pill` 里 |
| 提到一张截图，但观众不用细读（「有人复审成功了」「收到了这封邮件」） | `full` | `overlay: {type: 'pics'}`：截图浮在头顶上方，人脸不缩；`crop` 只露那一块；一句话前后讲两件事用 `then` 中途换图；两三张同时出现（如几期封面）写 `layout: 'fan'` 叠着摊开 |
| 列几个结论 / 经过的几步，但人想一直露脸（竖屏真人口播最常见） | `full` | `overlay: {type: 'steps'}`：头顶一条半透明小条，**说到哪条出哪条、一次只出一条**；`mark` 用 ok / no / maybe 标结论 |
| 进入新的一部分 | `full` | `overlay: {type: 'chapter'}` |
| 观点、感受、过渡、开头结尾 | `full` | 不配，或叠一个 `note` / `tag`。观点句留给人脸 |

- **画面从哪来，按这个顺序想**：有真素材（截图、录屏）用真的 → 没有但讲的是动作，用动作卡演出来 → 确实只是几个并列要点，才用文字清单。写分镜之前先跑 `npm run needs` 对一遍素材，缺的问用户能不能补。
- **叠在人像上的章节卡、便签、小标签不能压到脸**：位置是程序按脸选的（头顶上方或胸口）。检查器报「会压到脸」，就把字改短或这一镜不放。
- **每张卡都要过一关：观众第一次看、没有上下文，看到它能明白什么？** 把答案写在这一镜的 `why` 里（一句话）。写不出来的卡就删。完整范例见 `example.md`。
- **卡上的字不要和你说的话一字不差**：字幕已经有那句话了。卡上放结论、数字、对比，或者比原话短得多的标题。
- **开头三秒不能只有人在说话**：先放最抓人的结果或素材，至少叠一个便签。
- **真的就放真的，编的要标出来**：截图、录屏用真的；自己拼的界面、聊天、数据加 `mock: true`（角上标「示意」）。不用真实品牌的 logo。素材里没有的不编。
- **截图露出来的内容要和这一镜说的话对得上**：一张截图上常常有好几条消息，只有一条是你在讲的。写好 `crop` 以后用 `node tools/measure.mjs --text 图 --crop x,y,宽,高` 看这一块到底露出了什么；`npm run storyboard` 导出的分镜表末尾也会列出每张截图露出来的字。不相干的消息混在里面，就把 `crop` 收小。
- **同一张图的同一块只用一次**：隔开几镜又放一遍，观众会以为画面重复了（检查器会提醒）。先放全貌、紧接着放大细节可以。
- 截图里的名字、公司名、金额、邮箱要糊：写 `mask: ['email', 'money', '某某公司']`，只糊那几个字（见 `masking.md`）。
- 连续只有人在说话别超过 10 秒（`npm run check` 会提醒）。
- 同一段录屏连着讲几句：写成几镜、每镜一个 `screen`，后面的镜不写 `start` 就是接着往下放，中间不会重新弹出来。
- 素材里没有的画面不要编。没有合适素材的句子就用 `full`。

## 真人口播：脸优先（用户一再强调的）
口播号的观众是来看这个人的。人像能不缩就不缩：
- **先问自己：这张图观众要不要读里面的字？** 不用读（只是证明「真有这回事」）→ `pics` 浮在头顶，脸照常出镜；要逐字读（模板、长段文字、要框重点）→ 才用 `pip` 把人缩成小头像。一期里缩脸的镜头尽量只留两三处。
- **清单不要做成一整张大卡一直挂着**：大白卡挡画面，而且字全摆出来观众就不听了。用 `steps`，说到哪条才出哪条，上一条随即收走。弱一点的模型最爱画大卡，这条要特别守。
- **浮图不加白边**，只要圆角 + 阴影；加白框会显得像贴纸，很怪。
- **浮图和小条都在头顶上方，不能压到眉毛，更要留出头发**：画面顶到发际线，看着像人被截掉一块。检查器会按量出来的脸位算位置；改了 `layout` 或张数要重出静帧看一眼。
- **开头要两张图同时证明一件事**（比如两期的播放量），用 `layout: 'fan'` 同时出现，别一张一张轮着放。
- `at` 的词在这一镜里说了不止一次，写 `'护照#2'` 指第二次。

## 写进模板：`template/src/shots.js`
不写秒数。每一镜写它对应哪几句话（句子编号在 `src/sentences.js`），时间由程序算：
```js
{say: 'S04-S05', state: 'pip',
  card: {type: 'image', img: 'chat.png', caption: '它发来的消息',
    focus: [{text: '面试邀请', at: '面试'}], pill: '四天就约到了'}},
{say: 'S06', state: 'full', overlay: {type: 'note', text: '全程我只点了确认'}},
```
- `say`：`'S03'`、`'S03-S05'` 或 `['S03', 'S04']`。**每句话都要归到一镜**，按说话顺序往下排；只是人在说话的句子写 `state: 'full'`。
- 卡片有哪些、每种能填什么、例子：在 `template/` 里跑 **`npm run cards`**（以它为准）。
- **什么时候出现**：清单的每一条、要框的每一处，默认自动对到你说的词上（清单第 2 条 = 你说到第 2 条的时候）。想自己指定就写 `at`：`{text: '比人声小', at: '人声'}` = 说到「人声」时出现。`at` 里的词必须是这一镜的句子里真的说了的。
- **框重点 `focus`**：写图上的字 `{text: '打开浏览器'}`，位置由 `npm run measure` 去找；找不到它会列出图上认出来的字，照着改。不要自己估坐标。不知道图上有哪些字：`node tools/measure.mjs --text 截图.png`。
- **录屏 `screen`**：`start` 是从录屏的第几秒开始放。要让画面对到话上：说到某个动作时，录屏正好放到那个动作。
- 写完跑 `npm run check`，照提示改到没有错误。

## 给人看的分镜表
`npm run storyboard` 会把 `shots.js` 导出成一张表（`out/分镜表.md`：第几镜、时间、你说、画面、什么时候出现），`npm run stills` 出每一镜的静帧。两样一起发给用户，表头已经写了「想改哪里，直接用大白话说『第几镜换成什么』」。

## 加新的卡片类型
在 `template/src/schema.js` 登记字段（检查器和卡片菜单会自动跟上），在 `src/Film.jsx` 里照现有组件写一个、加进 `CARDS`，需要按说话时间出场的元素在 `src/resolve.js` 里算节拍，音效在 `src/sfx.js` 的 `buildSfx` 里登记。
