# 剪口播：从原始素材到剪紧的口播

口播没剪过，就走这三步（都在 `template/` 里）。口播已经剪好了，直接放到 `public/`，跳过这一页。

1. 原始口播放进 `raw/`（可以不止一条，按文件名顺序接；另外录的声音也放这里）→ `npm run raw`
2. 在 `src/takes.js` 里挑要留的句子（只改 `keep` 和 `text`）
3. `npm run cut` → 得到 `public/talk.mp4` 和句子时间轴

你不用算任何秒数：下刀的位置是程序按量出来的停顿定的，落在两句话之间的安静处。

## 第 2 步怎么挑：哪些句子不要

通读 `src/takes.js`，把不要的句子改成 `keep: false`。

**先核对程序标出来的**（带 `why` 的）。它只认得字面上「同样的话说了两遍」，会标错，标错了改回 `keep: true`。

**再找程序认不出来的**，一句一句往下读：
- **说到一半换了说法重来**：前一句没说完、没有结论，后面换个开头把同一件事重说了一遍。句子停在「也就是说……的」「它是一个……」「接下来就意味着」这类半句上，后面又停了一下（清单里标着「停了 X 秒」）的，多半就是。留后面完整的那一遍。
- **同一句开头出现两三遍**：留最后完整的一遍，前面几遍都不要。
- **和内容无关的话**：「好，开始」「再来一遍」「等一下」、跟旁边人说的话。
- 带 `note` 的句子，是程序拿不准、请你看一眼的。

**不要当成重讲剪掉的**：
- 缩写后面紧跟一遍读法（「R-A-G，rag」）——是有意的。
- 排比（「一个叫动态，一个叫点子」「早上喝水，下午喝水」）——开头一样，但说的是不同的事。
- 有意的重复强调。

拿不准的留着，并在交给用户时说明「这句我没敢剪」。**把「去掉了哪几句、为什么」列给用户看**，他同意再剪。

识别错的字可以顺手改 `text`（剪完再在 `sentences.js` 里改也行）。不要改 `id / clip / from / to`，不要增删行、调换顺序。

## 问用户的两件事（写进 `src/config.js` 的 `cut`）

| 设置 | 选项 |
|---|---|
| `pause` 气口留多长 | `'tight'` 紧，约 0.35 秒（节奏快的教程、观点类，默认）／`'loose'` 松，约 0.8 秒（讲故事、想留一点呼吸）／`'keep'` 原样，只把超过 1.5 秒的收到 0.8 秒（粗剪） |
| `speed` 要不要加速 | `npm run raw` 会报语速和建议。日常聊天约 4–5 字/秒，节奏紧凑的口播约 6.3–6.6 字/秒。常用 1.1 或 1.2；音调不变。**用户说了才加** |

「快」的感觉主要来自去掉气口，不一定靠加速。可以先 `npm run cut -- --dry` 看会剪成多长。

## 剪完看验收报告

`npm run cut` 最后会把剪好的口播重新量一遍：
- 「可能切到字」的刀口：去掉的那句和留下的那句之间没有停顿时，只能切在连着说的话中间。照它给的秒数听一下；切到字了，就把相邻那句也一起去掉或一起留下。
- 「声音很弱」的句子：多半是杂音被识别成了话，在 `takes.js` 里改成 `keep: false` 重剪。
- 每一段对应原片哪里，见 `out/剪辑表.md`。

重新剪过以后句子编号会变。分镜表已经写了的话，跑 `npm run check` 对一下。

## 这一步不做的事
- 不降噪（降过头声音会发闷、有「AI 味」）、不调色。
- 不改句子的先后顺序。要调顺序，把素材拆成几条、按想要的顺序命名。
- 素材结尾和下一条开头重录了同一段话：程序会留后一条里的那遍。

## 另外录的声音
电脑或录音笔录的更清楚的声音放进 `raw/`，`npm run raw` 会按波形把它和每条素材自动对齐（一条录音里包含好几条素材也行），剪的时候用它替换手机的声音。对不上或头尾差得多，它会说明，那条就用素材自己的声音。
